# Initial findings — 2026-10-18

This record preserves the evidence that motivated the skill. It is not a
certification, malware scan, or complete source audit.

- npm resolved `rea-agents@latest` to **6.7.0** at inspection time.
- Its declared Node range was `^22.19.0 || ^24.11.0 || >=26.0.0`.
  The host's Node 25 was incompatible; a temporary Node 24.22.0 binary ran the
  read-only preview. No persistent host REA runtime was installed.
- The downloaded archive matched npm's published integrity value:
  `sha512-yhIx2ioJYYT1C/tONfYeitC6LhnKmCh+ZwRUOgYuhSc733lGhkkt73zhug9WmLgxoMdKuqIYGCoBfD4fXkOhFw==`.
  This establishes archive consistency with registry metadata, not benign code.
- npm metadata advertised signatures/provenance; their presence was observed,
  but no independent attestation verification was completed.
- `npm audit --omit=dev --json` reported zero known vulnerabilities in the
  dependency tree inspected for the preview. The [saved report](evidence/npm-audit-rea-6.7.0-preview-2026-10-18.json)
  and [scope explanation](npm-audit.md) preserve this evidence. This does not exclude malicious
  packages, undisclosed flaws, or vulnerabilities introduced by a later build.
- REA setup returned `status: planned` and zero applied actions. Its default
  host connection would invoke `npx`; that plan was superseded by the user's
  container-only requirement.
- Docker Desktop **4.41.2** was installed. The engine returned HTTP 500 and was
  stuck in `stopping`; a normal start did not repair it, and a normal restart
  timed out. No factory reset, prune, or deletion of Docker data was performed.
- The installed Desktop release preceded the fix for CVE-2025-9074. The
  [official advisory](https://docs.docker.com/security/security-announcements/#docker-desktop-4443-security-update-cve-2025-9074)
  describes access from malicious containers to Docker Engine without a socket
  mount. The authorized update completed to **4.95.0**; the engine now reports
  **29.8.2**, runs Linux ARM64, and is reachable. Existing Docker data was not reset.
- The reviewed official Node image manifest included Linux ARM64 and AMD64.
  Its pinned index digest is recorded in the bundled Dockerfile.

Hostnames, personal paths, credentials, analyzed files, and raw diagnostics are
intentionally excluded from this repository. Native deployment results belong
in a separate validation record; these historical findings do not imply the
later installation or agent-tool boundary passed.
